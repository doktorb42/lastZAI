LAST Z / PEVA — FINAL WORKING SOLUTION
=======================================

STATUS: PASS — raw incoming chat capture works without OCR.

Root cause
----------
The prior patch targeted the obsolete l_slg_all ChatNetManager.  The active
runtime implementation is instead the base class required by the wrapper:

  SlgEngine.Chat.Controller.ChatNetManagerBase

It is stored in the active route discovered from the packaged gameres manifest:

  bundle:  slgengine_main_luatxt_chat_all_0290534658a2bf1172fe1b39063663e2.bundle
  asset:   Assets/SlgEngine/Main/LuaTxt/Chat/Controller/ChatNetManagerBase.bytes
  path_id: 6408915687859991957

The post-update loader may retain a downloaded CDN manifest alongside the APK.
The updater therefore patches, embeds and signs all three related APK entries:
the chat bundle, gameres and gameres.version.  It uses the active CDN manifest
version (2142 during this verification), so startup skips a needless manifest
download.  The final runtime test proves that the active ChatNetManagerBase is
loaded from the signed patched APK route even with the current local manifest.

Exact Lua changes
-----------------
The updater discovers the asset and refuses unknown bytecode shapes.

  1. 14 Lua short-string constants: ChatPrint -> print
  2. Callback-local instruction at normalized byte offset 3485:
       80 03 01 00   (MOVE 7 1)
       80 03 02 00   (MOVE 7 2)

The second change makes the callback print the JSON payload argument rather
than the old non-payload argument.  The saved bundle is reopened with UnityPy
and its TextAsset bytes must exactly match the replacement before any APK is
created.

chat_capture.py and adb_controll.py now accept both protocol names:

  push.chat.up.room

The latter is emitted by some current Last Z callbacks.  chat_capture.py also

messages containing emoji and passed strict UTF-8 validation.

Repeatable updater
------------------
Final updater:

  apply_lastz_chat_capture_patch.ps1

It dynamically discovers the current manifest route and validates all known
Lua invariants before changing anything.  It never overwrites source APKs.
It repacks with UnityPy packer="original", updates only the target manifest
CRC/size, writes the matching gameres.version, signs all splits and installs
through a verified Android install session.

Normal re-installation over the current local debug-signed build:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\projekty\lastZAI\apply_lastz_chat_capture_patch.ps1" -Install

After replacing the installed game with an official/store-signed update, first
place that update's three current APK splits in apk\current\ (base.apk,
split_config.arm64_v8a.apk, split_install_time_pack.apk), then use this one
command:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\projekty\lastZAI\apply_lastz_chat_capture_patch.ps1" -Install -Reinstall

The explicit -Reinstall is necessary because Android refuses an in-place
signature change.  The script backs up external app files first; without root,
Android does not permit restoration of private internal app data after an
uninstall.
